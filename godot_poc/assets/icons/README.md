# 图标规范（assets/icons）

这套图标是**手写 SVG**，不是 AI 生成、也不是图标库直接拷。

## 为什么不用 AI 生图或位图

- **AI 生图做不了图标**：图标要求同一条视觉基线——线宽、圆角半径、视觉重心、留白边距、
  光学居中——十五个图标里只要有一个重心偏 0.5px，并排显示时就会「跳」。生图模型每张都在重采样，
  无法稳定命中这些几何约束。
- **位图做不了多档尺寸**：图标要在 12–24px 之间多档使用。位图缩小要靠重采样，
  12px 时笔画会糊成灰雾；SVG 每个尺寸重新光栅化，等于真矢量。

图标库（Feather / Lucide / Tabler）可以借形状，但**必须统一改写**到本规范，
否则混进来一个 2px 线宽或 20×20 viewBox 的图标，整排都会显得脏。

## 几何规范

| 项 | 值 | 说明 |
|---|---|---|
| viewBox | `0 0 24 24` | 固定，缩放由渲染器负责 |
| 内容安全区 | 3 … 21 | 四周各留 3 单位，防止 12px 下贴边被裁 |
| `fill` | `none` | 一律描边，不用面 |
| `stroke` | `currentColor` | 由代码替换成目标色，**不要在文件里写死颜色** |
| `stroke-width` | `1.8` | 基准值。代码按显示尺寸自动加粗到 2.0 / 2.4，**不要手改** |
| 端点 / 拐角 | `round` | `stroke-linecap` 与 `stroke-linejoin` 都用圆头 |
| 视觉重心 | 居中 | 用「外接框」居中，不用「墨迹面积」居中；带尖角的形状需手动补偿 |

## 小尺寸必须加粗

`1.8` 的线画在 24 单位画布上，渲染到 13px 时只有 `13/24 × 1.8 ≈ 0.98` 像素宽——
**不足 1 像素的线会变成半透明灰雾**。这是图标设计里最常被忽略的一条。

`ui/icons.gd` 的 `_stroke_for()` 已经按尺寸接管：

| 显示尺寸 | 实际线宽 |
|---|---|
| ≤ 14px | 2.4 |
| ≤ 18px | 2.0 |
| > 18px | 1.8 |

所以 SVG 文件里永远写 `1.8`。

## 12px 是唯一的验收档位

这套图标实际只用三个尺寸：**12px（chip 里）/ 26px（卡面占位水印）/ 32px（空态与图鉴）**。
其中 12px 决定生死——26px 能读出来的形状，12px 不一定行：

- **细节会消失**：齿轮的齿（0.7px）、螺丝的螺纹、扳手的开口在 12px 下全部糊掉。
  所以「报修」最后用的是**锤子**——一个粗横块 + 一根柄，轮廓撑得住。
- **细长形状撑不住**：同一轮里试过的斜置扳手，在 12px 下只剩一根斜线，读不出是工具。
- **粗块面优先**：房屋、气泡、烧瓶、圆环十字、旗子都能活到 12px，因为它们的主体是一块，
  不是一组线。

配套工具 `tools/icon_sheet.gd` 会把每个图标按 32/16/12 三档渲染、12px 那档最近邻放大 4 倍，
并打印每个图标的**外接框与光学尺寸**（占 24 网格的百分比）——并排看「一大一小」就是靠这个数字发现的。

顶栏按钮自带文字，图标只做扫视定位，所以**只做能撑住 12px 的 4 个**：

| `load.svg` | 读档 | 向上箭头 + 托盘 | |
| `sound_on.svg` | 音效开 | 喇叭 + 两道声波 | 声波在 12px 下必然糊，见「已知限制」 |
| `sound_off.svg` | 音效关 | 喇叭 + 叉 | 叉比声波粗，12px 下反而比开态更清楚 |

**为什么不是 6 个**：原计划里还有「剩余刻」和「换签」。前者是顶栏的一行文字而不是按钮，
不需要图标；后者的通用形状是旋转箭头（3/4 圆环 + 箭头），在 12px 下只剩一个断环，
所以**没有做**——加一个必然糊的图标，比不加更差。

## 加一个新图标

1. 在 `assets/icons/` 新建 `<name>.svg`，照抄上面的规范（可以直接复制任意现有文件改 path）；
2. 把 name 加进 `tools/icon_sheet.gd` 的 `NAMES`（三组用 `GAP_AFTER` 隔开）；
3. 跑对照图：
   ```bash
   godot --headless --path . --script tools/icon_sheet.gd
   ```
   输出在 `user://icons_sheet.png`（同时拷一份到 `_shots/`）；
4. **必须看最小那一行**（12px 最近邻放大 4 倍）。看不懂就重画，不要靠「大概能看」交付；
5. 跑测试：`python -m unittest tests.test_godot_icons`。

## 验收标准

- [ ] 12px 下能认出是什么（把像素放大看，不是眯眼猜）
- [ ] 单独看和并排看都不歪（重心问题只在并排时暴露）
- [ ] 光学尺寸落在 70–88%（`icon_sheet.gd` 会算），差太多并排就是「一大一小」
- [ ] 线宽与现有图标的观感一致（不是数值一致，是**看起来**一致）
- [ ] 文件里没有硬编码颜色，只有 `currentColor`

## 实测记录

| 轮次 | 做法 | 结论 |
|---|---|---|
| 1 | 6 个指标图标 | 手写 15–20 分钟/个；`stress` 与 `inflammation` 各返工一次 |
| 2 | 9 个类型图标 | 「日出」与「斜置扳手」在 12px 下均判为不可读，当天推翻重画 |
| 3 | 报修三候选（锤子 / 铃 / 电话）同图对照 | 选锤子：唯一一个在 12px 下仍是「块 + 柄」两个质量 |
| 4 | 4 个顶栏 + 5 个状态 | `st_palpitation` 第一版是完整 ECG，12px 下变成「十」字，当场砍成单峰；`st_reflux` 第一版读作「上传」且与 `load` 撞形，改成拱形折返 |
| 5 | 顶栏 `Button.icon` 接线 | 发现 2x 超采样贴图会按原始像素（26px）占位，按钮被撑高 3px、图标与文字之间空出一大块；`icon_max_width` 掐到 13 才对齐（`tools/topbar_probe.gd` 量的是「带/不带图标的宽度差必须 = 18」） |
| — | 验收方式 | 本轮起主要靠**数值**验收（外接框、光学尺寸、`chip_probe` 的宽度差 16px、手牌宽高 152/216 全相等）。截图人眼复核仍应在真机上补，尤其是 12px 一行 |

### 已知限制

- `order_common`（锤子）在 12px 下读作「T」，靠 chip 里的「报修」二字消歧；
  26px 以上是清楚的锤子。若将来要单独使用（不放文字），需要重画带爪的羊角锤。
- **声波在 12px 下不可表达**，这是尺寸的物理极限，不是画法问题：`sound_on` 的两道弧
  在 12px 下会并成一团，`sound_off` 的叉也会缩成一点。两个按钮靠文字「音效 开/关」区分，
  图标在 16px 以上才各自清楚。如果将来要单独使用（不放文字），需要换一个非声波的隐喻。
- `st_insomnia`（床）在 12px 下只剩「一条横线 + 一根竖线 + 一个小方块」，读作床是
  靠上下文。它是这套里语义最弱的一个。
- 图标目前在 Godot 端接进了三处（卡面 chip、工单 chip、状态行）+ 两处（卡面占位条、顶栏按钮）；
  网页版仍是纯文字 chip，两端在这一层**有意不同**——网页端是旧版保留，改动以 Godot 为准。
